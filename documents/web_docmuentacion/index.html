RA1 — Informe de Diseño Introducción

Introducción

Propósito, alcance y contexto del sistema EcoRuteando.

EcoRuteando es una aplicación móvil y web diseñada para la ciudad de Neiva que promueve la movilidad urbana sostenible. Permite a sus habitantes planificar recorridos en bicicleta o transporte público, ofreciendo rutas que contaminan significativamente menos que el uso del automóvil particular. Cada kilómetro recorrido queda documentado con su ahorro real de CO₂, construyendo un historial colectivo del impacto ambiental positivo de la ciudad.
Propósito del documento
Describir la arquitectura técnica, los componentes y las decisiones de construcción del software, sirviendo como guía completa para el equipo de desarrollo.
Alcance del sistema
Aplicación web responsiva para Neiva con planificación de rutas ecológicas, cálculo automático de CO₂ evitado, comunidad de ciclistas y alertas climáticas en tiempo real.
Usuarios objetivo
Estudiantes universitarios, trabajadores urbanos, ciclistas y ciudadanos comprometidos con el medio ambiente en la ciudad de Neiva, Huila.
Documentos relacionados
Especificación de Requisitos (SRS), Script DDL de base de datos, Maquetas Figma, Repositorio GitHub y diagramas UML del sistema.
Definiciones y términos clave
  • CO₂ — Dióxido de carbono. Unidad de medida del impacto ambiental. Factor: 0.192 kg/km en auto (Min. Ambiente Colombia).
  • SRS — Documento de Especificación de Requerimientos del Software.
  • PostGIS — Extensión de PostgreSQL para datos geográficos (coordenadas GPS, trayectos, áreas de impacto).
  • JWT — JSON Web Token. Mecanismo de autenticación segura para las sesiones de usuario.
  • API REST — Interfaz de Programación de Aplicaciones basada en arquitectura REST para comunicación entre servicios.
  • JSONB — Formato de almacenamiento binario de JSON en PostgreSQL, usado para guardar respuestas de APIs externas.
RA1 Descripción General del Sistema

Descripción General del Sistema

Objetivo, funcionalidades principales y contexto de operación en Neiva.

EcoRuteando opera en entornos urbanos integrando datos de mapas (Google Maps API), condiciones climáticas (OpenWeather) y transporte público de Neiva para ofrecer las rutas más sostenibles. El sistema calcula automáticamente el CO₂ ahorrado en cada trayecto usando los factores del Ministerio de Ambiente de Colombia: 0.192 kg de CO₂ por kilómetro en automóvil.

RA1 Diseño de Componentes o Módulos

Diseño de Componentes o Módulos

Descripción detallada de cada módulo del sistema, sus entradas, procesos y salidas.

Módulo 1 — Seguridad y Usuarios

Gestiona el ciclo de vida completo del usuario: registro, verificación de correo, inicio de sesión con JWT, autenticación OAuth con Google/Facebook, doble factor (2FA) y recuperación de contraseña. Incluye un sistema completo de roles y permisos (invitado, usuario, moderador, administrador).

  • Entradas: Datos de registro, credenciales, tokens OAuth
  • Procesos: Hash de contraseñas (bcrypt), generación JWT, bloqueo automático tras 5 intentos fallidos
  • Salidas: Sesión activa, perfil de usuario, log de auditoría
Módulo 2 — Rutas y Movilidad

Núcleo del sistema. Almacena la geometría real de cada ruta usando PostGIS con coordenadas GPS de cada curva del camino. Un trigger calcula automáticamente el CO₂ ahorrado (0.192 kg/km) y las calorías quemadas. Los datos completos de Google Maps se guardan en formato JSONB.

  • Entradas: Origen/destino, tipo de transporte, respuesta de Google Maps API
  • Procesos: Cálculo de distancia PostGIS, trigger CO₂, almacenamiento JSONB
  • Salidas: Ruta con trayecto GPS, CO₂ evitado, tiempo estimado, puntos de interés
Módulo 3 — Datos Externos / Caché

Gestiona la integración con APIs externas (Google Maps, OpenWeather). Para evitar costos excesivos, implementa un sistema de caché con TTL configurable: primero busca en cache_apis y solo llama a la API externa si el caché venció. También almacena datos climáticos y de calidad del aire.

  • Entradas: Peticiones de rutas, consultas de clima
  • Procesos: Verificación TTL, llamada condicional a APIs externas, almacenamiento de respuesta
  • Salidas: Datos de mapa, condición climática, índice de calidad del aire
Módulo 4 — Comunidad y Reportes

Permite a los usuarios reportar obstáculos en rutas (baches, obras, inundaciones) con ubicación exacta en el mapa. Otros usuarios votan para confirmar o descartar el reporte. Los moderadores lo validan, apareciendo en el mapa para advertir a todos los ciclistas. Incluye calificaciones de 1 a 5 estrellas con votos de utilidad.

Módulo 5 — Alertas

Crea alertas con área geográfica de impacto. Gracias a PostGIS, la BD calcula automáticamente qué rutas pasan por el área afectada y las marca. Tipos: clima, obstáculo, mantenimiento, evento y emergencia.

Módulo 6 — Notificaciones

Envía alertas al usuario por cuatro canales: in-app, correo electrónico, push al celular y SMS. Usa plantillas predefinidas con variables dinámicas como {{nombre}} que el backend reemplaza antes de enviar.

RA1 Diseño de Base de Datos

Diseño de Base de Datos

Modelo relacional PostgreSQL 16 + PostGIS — 8 módulos, 30+ tablas.

La base de datos es el "cerebro" de EcoRuteando. Guarda absolutamente todo lo que ocurre en la app: perfiles de usuarios, trayectos GPS completos, cálculos de CO₂, reportes ciudadanos, alertas climáticas con área de impacto geográfica y un registro de auditoría que captura cada acción. Usa PostGIS para manejar geometrías reales (puntos, líneas, polígonos) en coordenadas GPS.

Tabla: usuarios (Módulo Seguridad) 
CREATE TABLE usuarios (
    id_usuario      UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    nombre          VARCHAR(100) NOT NULL,
    apellido        VARCHAR(100),
    correo          VARCHAR(150) NOT NULL UNIQUE,
    password_hash   VARCHAR(255),           -- NULL si usa OAuth
    telefono        VARCHAR(30),
    foto_perfil_url VARCHAR(500),
    acepto_terminos BOOLEAN NOT NULL DEFAULT FALSE,
    correo_verificado BOOLEAN NOT NULL DEFAULT FALSE,
    estado          estado_usuario DEFAULT 'ACTIVO',
    es_invitado     BOOLEAN DEFAULT FALSE,  -- acceso sin registro
    id_rol_principal INT REFERENCES seg_roles(id_rol) ON DELETE SET NULL,
    intentos_fallidos INT DEFAULT 0,
    bloqueado_hasta TIMESTAMP WITH TIME ZONE,
    ultimo_acceso   TIMESTAMP WITH TIME ZONE,
    creado_en       TIMESTAMP WITH TIME ZONE DEFAULT now(),
    actualizado_en  TIMESTAMP WITH TIME ZONE DEFAULT now()
);
Tabla: rutas (Módulo Rutas — tabla principal) 
CREATE TABLE rutas (
    id_ruta             UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    nombre              VARCHAR(150) NOT NULL,
    descripcion         TEXT,
    tipo_transporte     tipo_transporte NOT NULL,  -- bicicleta | mixto | ...
    estado              estado_ruta DEFAULT 'activa',
    nombre_inicio       VARCHAR(200) NOT NULL,
    nombre_destino      VARCHAR(200) NOT NULL,
    geom_inicio         GEOGRAPHY(POINT, 4326),    -- PostGIS punto origen
    geom_fin            GEOGRAPHY(POINT, 4326),    -- PostGIS punto destino
    trayecto            GEOGRAPHY(LINESTRING, 4326), -- recorrido GPS completo
    polyline_encoded    TEXT,                      -- encoded polyline Google Maps
    distancia_km        NUMERIC(10,2),
    tiempo_estimado_min INT,
    co2_ahorrado_kg     NUMERIC(10,4),  -- calculado por trigger automático
    calorias_estimadas  NUMERIC(8,2),
    dificultad          SMALLINT CHECK (dificultad BETWEEN 1 AND 5),
    datos_mapa          JSONB,          -- respuesta completa DirectionsAPI
    creado_por          UUID REFERENCES usuarios(id_usuario) ON DELETE SET NULL,
    creado_en           TIMESTAMP WITH TIME ZONE DEFAULT now()
);
Tabla: uso_rutas (historial de trayectos) 
CREATE TABLE uso_rutas (
    id_uso            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    id_usuario        UUID NOT NULL REFERENCES usuarios(id_usuario) ON DELETE CASCADE,
    id_ruta           UUID NOT NULL REFERENCES rutas(id_ruta)       ON DELETE CASCADE,
    modo_transporte   tipo_transporte,
    inicio            TIMESTAMP WITH TIME ZONE DEFAULT now(),
    fin               TIMESTAMP WITH TIME ZONE,
    finalizado        BOOLEAN DEFAULT FALSE,
    distancia_real_km NUMERIC(10,2),    -- GPS real del celular
    duracion_real_min INT,              -- calculado por trigger al finalizar
    co2_real_kg       NUMERIC(10,4),    -- CO₂ real ahorrado en este trayecto
    trayecto_real     GEOGRAPHY(LINESTRING, 4326), -- línea GPS real
    datos_gps         JSONB,            -- [{lat, lon, ts, vel_kmh}]
    origen            VARCHAR(10) DEFAULT 'web' CHECK (origen IN ('web','movil','pwa'))
);
Tabla: reporte_obstaculos (Módulo Comunidad) 
CREATE TABLE reporte_obstaculos (

    id_validador    UUID REFERENCES usuarios(id_usuario) ON DELETE SET NULL,
    nota_validacion TEXT,
    validado_en     TIMESTAMP WITH TIME ZONE,
    rutas_afectadas JSONB,  -- UUIDs de rutas que cruzan este punto

    fecha           TIMESTAMP WITH TIME ZONE DEFAULT now()

RA1 Reglas de Negocio

Reglas de Negocio

Restricciones, políticas y lógica que rigen el comportamiento del sistema.

CódigoRegla
RN-01El usuario invitado solo puede visualizar rutas; para calificar o reportar debe registrarse.
RN-02El CO₂ ahorrado se calcula automáticamente con el factor del Min. Ambiente: 0.192 kg/km en auto.
RN-03Tras 5 intentos fallidos de contraseña, la cuenta se bloquea automáticamente 30 minutos.
RN-04Solo el administrador puede eliminar rutas o usuarios del sistema.
RN-05Un usuario puede votar en el mismo reporte de obstáculo una sola vez.
RN-06Las estadísticas del dashboard se precalculan cada noche; no se calculan en tiempo real.
RN-07El caché de Google Maps expira en 3600 s y el del clima en 1800 s según configuración.
RN-08Las alertas climáticas vinculan automáticamente (PostGIS) qué rutas pasan por el área afectada.
RN-09Toda acción importante (cambio de estado, validación, configuración) queda en seg_auditoria.
RN-10Un correo no puede registrarse dos veces en el sistema (campo UNIQUE en tabla usuarios).
RA1 Seguridad del Sistema

Seguridad del Sistema

Mecanismos de protección, autenticación, autorización y auditoría completa.

Autenticación JWT
Tokens de sesión con expiración, refresh token en BD (seg_sesiones) y revocación en logout. Access token solo en memoria del cliente, nunca persistido.
Roles y Permisos
4 roles: invitado, usuario, moderador, administrador. Sistema granular de permisos (seg_permisos) con acciones específicas por rol.
Doble Factor (2FA)
Soporte para TOTP, SMS y correo electrónico como segundo factor de autenticación (tabla seg_2fa).
Auditoría Completa
seg_auditoria registra quién hizo qué, cuándo, desde qué IP y cómo estaba el registro antes y después. Todo automático mediante triggers.
Políticas de Contraseña
Min. 8 caracteres, mayúsculas, números y especiales requeridos. Expiración cada 90 días. Bloqueo tras 5 intentos fallidos (seg_politicas).
Protección de Datos
Contraseñas con bcrypt, HTTPS obligatorio, sanitización contra SQL Injection y XSS. APIs secretas en variables de entorno del servidor, nunca en BD.

RA1 Consideraciones de Implementación

Consideraciones de Implementación

Factores clave a tener en cuenta durante el desarrollo del proyecto.

  • Ejecutar los scripts en orden: ddl.sql → indices.sql → funciones.sql → trigger.sql → vistas.sql → dml.sql.
  • Usar variables de entorno (.env) para credenciales, API keys y configuraciones sensibles. Nunca guardarlas en la BD.
  • Documentar la API con Swagger/OpenAPI para facilitar la integración frontend-backend.
  • El sistema de caché (cache_apis) debe verificar TTL antes de llamar APIs externas para reducir costos.
  • El cron job nocturno de estadisticas_diarias debe ejecutarse entre las 2:00 y 3:00 AM para no afectar el rendimiento.
  • Implementar pruebas unitarias con cobertura mínima del 70%. Los triggers de auditoría deben probarse independientemente.
  • Realizar copias de seguridad automáticas de PostgreSQL cada 24 horas con retención de 30 días.
  • Estándares de codificación: camelCase en C#/JS, snake_case en SQL, commits en español siguiendo Conventional Commits.

RA2 Justificación de la Selección

Justificación de la Selección

Razones técnicas y prácticas que respaldan cada herramienta elegida.

Visual Studio Code

Editor gratuito y de código abierto compatible con Windows, macOS y Linux. Sus extensiones para C# (OmniSharp), React, PostgreSQL y la integración nativa con Git lo hacen la elección más eficiente para el equipo.

C# — ASP.NET Core 8

Framework de Microsoft ampliamente probado en entornos empresariales. Facilita la creación de APIs REST con autenticación JWT integrada, Entity Framework para el ORM y excelente rendimiento bajo carga concurrente.

React 18

Biblioteca JavaScript de Meta para construir interfaces reactivas basadas en componentes reutilizables. Permite desarrollar el frontend de forma modular con alta interactividad, ideal para el mapa en tiempo real y el seguimiento de recorridos.

PostgreSQL 16 + PostGIS

Sistema de gestión de bases de datos relacional open source. La extensión PostGIS es imprescindible para EcoRuteando: permite almacenar trayectos GPS como líneas reales, calcular intersecciones de rutas con áreas de alertas y medir distancias geodésicas precisas.

Google Maps API

Servicio de mapas con la mayor cobertura de rutas de transporte público en ciudades colombianas. Proporciona datos precisos de ciclovías, tiempos y tráfico en Neiva. Las respuestas se guardan en cache_apis para controlar los costos.

Git + GitHub

Estándar de la industria para control de versiones. Permite trabajo colaborativo en ramas, revisión de código mediante Pull Requests, registro de todos los cambios y respaldo completo del proyecto en la nube.
